# UI Rules: Geometric Fillable Card UI

## 核心原则

这是 AI Meme Generator from Photo 的几何卡片式可填充 UI 方法。设计目标是让网站看起来年轻、轻松、专业、有产品感，同时方便后续用 Next.js + Tailwind CSS 实现。

## 1. 不要做普通官网模板

- 不做千篇一律的 SaaS 官网模板。
- 不依赖空泛的大标题、渐变背景和普通三栏卖点。
- 首页第一屏要直接呈现产品能力和 meme 生成体验。
- 页面视觉应该围绕“上传照片、填写文字、生成 meme”这个核心动作展开。

## 2. 页面功能区必须卡片化

- 每个主要功能区都应该被设计成独立卡片或卡片组。
- 上传区、编辑区、预览区、下载区、功能介绍、Pricing、FAQ、政策入口都应该有明确的卡片边界。
- 卡片之间通过留白、尺寸、颜色和层级区分信息关系。

## 3. 每个功能区都要有清晰的几何容器

- 每个功能区必须有清楚的几何容器，避免内容漂浮在页面上。
- 容器可以是大圆角矩形、长条卡片、双栏面板、网格卡片或折叠卡片。
- 几何容器需要支持内容填充，方便后续加入标题、文字、图标、按钮、标签和装饰元素。

## 4. 主要使用的 UI 形状

- 大圆角矩形：用于 Hero、上传区、编辑工作台、Pricing 主卡片。
- 长条卡片：用于步骤说明、功能亮点、信任说明、政策入口。
- 小卡片：用于功能点、FAQ、使用场景、对比信息。
- 胶囊按钮：用于主要 CTA、下载按钮、导航按钮、状态标签。

## 5. 每个卡片都要预留可填充槽位

每个卡片设计时都应该预留这些槽位：

- 标题槽位
- 副标题槽位
- 图标槽位
- 按钮槽位
- 标签槽位
- 装饰元素槽位

这些槽位不一定每张卡片都全部使用，但结构上要方便扩展，避免后续加内容时破坏布局。

## 6. PC 端布局规则

- 使用顶部导航。
- 使用大 Hero 区。
- Hero 区可以包含产品介绍、上传入口、预览卡片或生成器入口。
- 核心内容使用多列卡片网格。
- Pricing 使用价格卡片布局。
- FAQ 使用折叠卡片布局。
- 页脚放置 Privacy Policy、Terms of Service、Refund Policy、Contact 等页面入口。

## 7. 平板端布局规则

- 使用 2 列布局作为默认结构。
- 重要区域可以跨 2 列展示。
- 上传区和预览区可以上下排列，也可以左右并列，取决于屏幕宽度。
- 卡片间距要比 PC 端更紧凑，但仍保持清晰的几何分组。

## 8. 手机端布局规则

- 使用单列卡片布局。
- 风格接近小程序：清晰、直接、模块化。
- 上传、输入、预览、下载应按自然操作顺序排列。
- 按钮要足够大，适合触屏操作。
- 卡片宽度应接近满屏，但保留适当外边距。

## 9. SEO 与真实文本规则

- 网站要兼顾 SEO。
- 重要文字必须是真实文本，不能全部做成图片。
- 标题、卖点、Pricing、FAQ、政策说明、按钮文字都应该使用 HTML 文本。
- 图片和装饰元素只承担视觉增强作用，不替代关键信息。

## 10. Next.js + Tailwind 实现方向

- 页面结构应方便拆分为 Next.js 组件。
- 卡片样式应方便用 Tailwind CSS 复用。
- 布局优先使用响应式 Grid 和 Flex。
- 圆角、间距、阴影、边框、背景色要形成统一设计系统。
- 生成器核心交互使用前端 Canvas，图片只在浏览器本地处理，不上传服务器。
